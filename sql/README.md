# สคริปต์ SQL

รันที่ **Supabase Dashboard → SQL Editor**

---

## `ตรวจสุขภาพ/` — ใช้ซ้ำได้เรื่อยๆ

สคริปต์ที่ออกแบบให้รันเมื่อไหร่ก็ได้ **อ่านอย่างเดียว ไม่แก้ข้อมูล**

| ไฟล์ | ใช้เมื่อไหร่ |
|---|---|
| `ตรวจสุขภาพระบบ.sql` | อยากรู้ว่าระบบยังปกติดีไหม — สต็อก ออเดอร์ สิทธิ์ RLS |
| `พิสูจน์ว่าต้นทุนไม่รั่ว.sql` | สงสัยตัวเลขกำไร อยากไล่ดูว่า FIFO ตัดต้นทุนถูกจริงไหม |

**แนะนำให้รันเดือนละครั้ง** หรือทุกครั้งที่ตัวเลขในรายงานดูแปลก

## บทเรียนจากสคริปต์ในโฟลเดอร์นี้

เขียนไว้เพราะเคยพลาดมาแล้วจริง ครั้งหน้าจะได้ไม่ซ้ำ

**แบ่งเป็น "ดูก่อน" กับ "ทำจริง" เสมอ** ทุกไฟล์ที่ลบข้อมูลมี PART 1 ที่เป็น SELECT ล้วน
ให้ดูว่าจะกระทบอะไรก่อน แล้ว PART 2 ค่อยลบจริง

**ครอบ `BEGIN ... COMMIT` ทุกครั้งที่แก้หลายตาราง** ถ้าพังกลางทางจะย้อนทั้งก้อน
ไม่มีทางเหลือข้อมูลที่ลบไปได้ครึ่งเดียว

**ลบ `stock_movements` ต้องคืน `qty_remaining` ให้ล็อตด้วย**
คอลัมน์นั้นเป็นค่าจริงไม่ใช่ค่าคำนวณ ลบ movement เฉยๆ = สต็อกหายแบบไม่มีร่องรอย

**เช็ค foreign key ก่อนเขียนคำสั่งลบ** `receipts` `shipments` `returns` เป็น RESTRICT
ต้องลบก่อน ส่วน `orders.user_id` เป็น SET NULL — ลบผู้ใช้แล้วออเดอร์ไม่หาย

**อย่าเดาชื่อคอลัมน์** `notifications` ไม่มี `order_id` — เลขออเดอร์อยู่ใน JSON `payload`
เคยเขียนผิดเพราะคิดเอาเองว่าน่าจะเหมือนตารางอื่น

**อย่าใส่ตัวระบุตัวตนลูกค้าเต็มๆ ลงไฟล์** โฟลเดอร์นี้ขึ้น git ใช้เงื่อนไขแบบ
`line_user_id like 'Uxxxx%'` แทนการเขียน ID เต็ม
