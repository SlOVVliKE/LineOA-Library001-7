# แผนรื้อโครงสร้าง UX/UI หลังบ้าน

**ขอบเขต** หลังบ้าน 16 หน้า / 27 ไฟล์ · ออกแบบให้คอมเป็นหลัก · รื้อโครงสร้าง ไม่ใช่แค่ทาสีใหม่
**ไม่แตะ** หน้าร้าน — ทำเสร็จและลูกค้าใช้จริงอยู่แล้ว

---

## ส่วนที่ 1 — ปัญหาที่เจอจากการอ่านโค้ดจริง

### 1.1 เมนู 11 อันเรียงเรียบ ไม่มีลำดับชั้น

```
ภาพรวม · คำสั่งซื้อ · สั่งจอง · หนังสือ · หมวดหมู่ · ลูกค้าสนใจ ·
สต็อกและต้นทุน · รับสินค้าเข้า · ปรับสต็อก · รายงานกำไร · แจ้งเตือน
```

สิบเอ็ดอันวางเรียงกันหมดโดยไม่บอกว่าอันไหนเกี่ยวกับอันไหน คนใช้ต้องจำเอาเองว่า
"รับสินค้าเข้า" กับ "สต็อกและต้นทุน" เป็นเรื่องเดียวกัน ส่วน "ลูกค้าสนใจ" ไม่ใช่

### 1.2 เอา "การกระทำ" มาปนกับ "สถานที่"

`รับสินค้าเข้า` และ `ปรับสต็อก` เป็น**ฟอร์มที่ทำเป็นครั้งคราว** ไม่ใช่หน้าที่ต้องเปิดดูบ่อย
แต่ถูกวางอยู่ระดับเดียวกับ `คำสั่งซื้อ` ที่เปิดทุกวัน

แถมหน้า `สต็อกและต้นทุน` ก็มีปุ่มไปสองหน้านี้อยู่แล้ว — **ซ้ำซ้อนกันเอง**

### 1.3 หน้าแรกตอบผิดคำถาม

ตอนนี้หน้าแรกบอก: หนังสือที่เปิดขาย · จำนวนเล่มในสต็อก · มูลค่าสต็อก · ต้องสั่งเพิ่ม · ค้างเกิน 90 วัน

ทั้งหมดเป็น**ข้อมูลคลัง** แต่คำถามที่คนเปิดหลังบ้านตอนเช้าอยากรู้คือ
**"วันนี้ฉันต้องทำอะไรบ้าง"** — มีสลิปรอตรวจกี่ใบ ออเดอร์รอส่งกี่รายการ
คิวสั่งจองที่ของเข้าแล้วต้องจ่ายกี่คน แจ้งเตือนที่ส่งไม่สำเร็จมีไหม

ตอนนี้ต้องไล่เปิดทีละหน้าเพื่อประกอบคำตอบเอง

### 1.4 บอกว่าออกแบบให้คอม แต่โครงเป็นแนวตั้งแบบมือถือ

`max-w-7xl` กว้างพอ แต่ข้างในเป็นการ์ดเรียงลงมาทีละอัน
งานหลังบ้านคืองานตาราง — ต้องการความหนาแน่น หัวตารางที่ค้างไว้ตอนเลื่อน และการเรียงคอลัมน์

### 1.5 หน้าที่ใหญ่ที่สุดคือหน้าที่ทำงานหลายอย่างเกินไป

| ไฟล์ | ขนาด | ทำอะไรอยู่ |
|---|---|---|
| `orders/[id]/page.tsx` | 13.5 KB | รายการสินค้า · การเงิน · พัสดุ · ที่อยู่ · ใบเสร็จ · ปุ่มดำเนินการ |
| `stock/page.tsx` | 12.5 KB | สรุปยอด · กราฟรายวัน · ตารางล็อต · สต็อกคงเหลือ — **สี่งานในหน้าเดียว** |
| `reports/page.tsx` | 10.7 KB | สรุป · รายวัน · รายเล่ม · ค่าส่ง · ค้างสต็อก |

### 1.6 คนละภาษาออกแบบกับหน้าร้าน

หลังบ้าน **0 จาก 27 ไฟล์** ใช้ design token ที่วางไว้ตอนทำหน้าร้าน
ยังเป็น `teal-` `slate-` `gray-600` กระจายอยู่ทุกไฟล์ — สีและระยะห่างจึงไม่มีที่มาที่ไป

## ส่วนที่ 2 — โครงสร้างที่เสนอ

### 2.1 เมนูข้างแทนเมนูบน จัด 5 กลุ่ม

```
┌─────────────────┬──────────────────────────────────┐
│  ระบบร้านหนังสือ  │                                  │
│                 │                                  │
│  ▸ งานวันนี้      │        พื้นที่ทำงานเต็มความกว้าง      │
│                 │                                  │
│  ขาย            │                                  │
│    คำสั่งซื้อ  ③  │   ← ตัวเลขบอกว่ามีงานค้างกี่ชิ้น      │
│    สั่งจอง        │                                  │
│                 │                                  │
│  สินค้า          │                                  │
│    หนังสือ       │                                  │
│    หมวดหมู่      │                                  │
│    ลูกค้าสนใจ    │                                  │
│                 │                                  │
│  คลัง            │                                  │
│    สต็อกและต้นทุน │                                  │
│                 │                                  │
│  รายงาน          │                                  │
│    กำไร          │                                  │
│                 │                                  │
│  ระบบ            │                                  │
│    แจ้งเตือน  ①  │                                  │
└─────────────────┴──────────────────────────────────┘
```

**จาก 11 อันเหลือ 8** เพราะ `รับสินค้าเข้า` และ `ปรับสต็อก` ย้ายไปเป็นปุ่มในหน้าคลัง
ซึ่งเป็นที่ที่คนอยู่ตอนจะทำสองอย่างนั้นพอดี

**ทำไมเมนูข้าง** — จอคอมกว้างแต่ไม่สูง เมนูข้างกินความกว้างที่มีเหลือเฟือ
แลกกับความสูงที่หายาก และรองรับการจัดกลุ่มโดยไม่ต้องใช้ dropdown

**ตัวเลขข้างเมนู** คือหัวใจ — เห็นตั้งแต่แรกว่ามีอะไรค้าง ไม่ต้องเข้าไปดูทีละหน้า

### 2.2 หน้าแรกใหม่: "งานวันนี้"

เรียงตามความเร่งด่วนจริง ไม่ใช่ตามหมวดข้อมูล

```
┌──────────────────────────────────────────────────┐
│  งานวันนี้                                        │
├──────────────────────────────────────────────────┤
│  🔴 สลิปรอตรวจ            2 ใบ    [ดู →]          │
│  🟡 ชำระแล้ว รอส่ง         3 ออเดอร์  [ดู →]          │
│  🟡 ของเข้าแล้ว รอจ่ายคิว    1 คน    [ดู →]          │
│  🔴 แจ้งเตือนส่งไม่สำเร็จ    1 รายการ [ดู →]          │
│                                                  │
│  ถ้าไม่มีอะไรค้าง → "วันนี้เคลียร์แล้ว ✓"            │
├──────────────────────────────────────────────────┤
│  สภาพคลัง                                         │
│  ต้องสั่งเพิ่ม 1 · ค้างเกิน 90 วัน 1 · มูลค่า ฿27,397  │
└──────────────────────────────────────────────────┘
```

**หลักคิด** — ของที่ต้องลงมือทำอยู่บน ของที่ไว้ดูเฉยๆ อยู่ล่าง
และถ้าไม่มีงานค้างต้องบอกให้ชัดว่าเคลียร์แล้ว ไม่ใช่โชว์ศูนย์เรียงกันให้ตีความเอง

### 2.3 หน้าคำสั่งซื้อ: แบ่งซ้าย-ขวา

ปัญหาปัจจุบัน: กดเข้าออเดอร์ → ทำงาน → กดย้อนกลับ → **เสียตำแหน่งที่ค้างไว้** → เลื่อนหาใหม่
ถ้ามีออเดอร์ต้องเคลียร์สิบรายการ ต้องทำวนแบบนี้สิบรอบ

```
┌────────────────────┬─────────────────────────────┐
│ รอชำระ │ รอส่ง │ ...  │  OD-2026-000003            │
├────────────────────┤  ┌───────────┬─────────────┐ │
│ ▸ OD-000003  ฿41   │  │ สินค้า      │ การเงิน      │ │
│   OD-000002  ฿360  │  │ ที่อยู่      │ [ปุ่มดำเนินการ] │ │
│   OD-000001  ฿885  │  │ พัสดุ       │  ← ค้างไว้     │ │
│                    │  └───────────┴─────────────┘ │
└────────────────────┴─────────────────────────────┘
```

เลือกออเดอร์ทางซ้าย รายละเอียดขึ้นทางขวา **รายการไม่หาย** เคลียร์งานต่อเนื่องได้

ปุ่มดำเนินการอยู่คอลัมน์ขวาแบบค้างไว้ ไม่ต้องเลื่อนลงไปหาทุกครั้ง

### 2.4 หน้าคลัง: แยกสี่งานเป็นสามแท็บ

| แท็บ | ตอบคำถาม |
|---|---|
| **สต็อกคงเหลือ** (ค่าเริ่มต้น) | ตอนนี้มีอะไรเหลือเท่าไหร่ ต้องสั่งอะไรเพิ่ม |
| **ล็อตและต้นทุน** | ของล็อตไหนเข้ามาเมื่อไหร่ ต้นทุนเท่าไหร่ FIFO จะตัดตัวไหนก่อน |
| **ความเคลื่อนไหว** | เดือนนี้ขายออกเท่าไหร่ รับเข้าเท่าไหร่ กราฟรายวัน |

ปุ่ม **รับสินค้าเข้า** และ **ปรับสต็อก** อยู่มุมขวาบนของทุกแท็บ
เปิดเป็นแผงเลื่อนออกมาด้านข้าง ไม่ใช่เปลี่ยนหน้า — กรอกเสร็จปิดแล้วยังอยู่ที่เดิม

### 2.5 ใช้ design system เดียวกับหน้าร้าน

เอา token ที่มีอยู่แล้วใน `globals.css` มาใช้ — ไม่ต้องสร้างใหม่

**แต่หลังบ้านต้องแน่นกว่าหน้าร้าน** เพราะดูบนคอมและต้องเห็นข้อมูลเยอะต่อหน้าจอ

| | หน้าร้าน (มือถือ) | หลังบ้าน (คอม) |
|---|---|---|
| ตัวอักษรพื้น | 15px | 14px |
| ความสูงแถวตาราง | — | 40px |
| ปุ่ม | สูง 48px | สูง 36px |
| ระยะห่างการ์ด | 14px | 10px |

เพิ่มชุด `.t-*` และ `.btn-*` เวอร์ชันหลังบ้านใน `globals.css` โดยใช้สีและฟอนต์ชุดเดิม

## ส่วนที่ 3 — ลำดับการทำ

แบ่งเป็น 4 รอบ **แต่ละรอบจบในตัวและ deploy ได้** ไม่ต้องรอครบทั้งหมด

| รอบ | ทำอะไร | ได้อะไร |
|---|---|---|
| **1** | เมนูข้าง 5 กลุ่ม + ตัวเลขงานค้าง + หน้า "งานวันนี้" | รู้ทันทีว่าต้องทำอะไร — เปลี่ยนความรู้สึกมากที่สุดต่อแรงที่ลง |
| **2** | หน้าคำสั่งซื้อแบบซ้าย-ขวา + หน้ารายละเอียดสองคอลัมน์ | งานที่ทำบ่อยที่สุดเร็วขึ้นชัดเจน |
| **3** | หน้าคลังสามแท็บ + ฟอร์มเป็นแผงเลื่อน | เลิกหลงทางระหว่างสามหน้าที่เกี่ยวกัน |
| **4** | หน้าที่เหลือ (หนังสือ หมวดหมู่ ลูกค้าสนใจ รายงาน แจ้งเตือน) | ทั้งระบบเป็นภาษาเดียวกัน |

**ทำไมเรียงแบบนี้** — รอบ 1 ให้ผลตอบแทนสูงสุดต่อแรงที่ลง และเป็นโครงที่รอบอื่นต้องอาศัย
รอบ 2 คืองานที่ทำทุกวัน รอบ 4 คือหน้าที่นานๆ เปิดที จึงไว้ท้ายสุด

## ส่วนที่ 4 — สิ่งที่จะไม่ทำ

เขียนไว้ให้ชัดเพื่อไม่ให้งานบานปลาย

- **ไม่แตะหน้าร้าน** — ทำเสร็จแล้วและลูกค้าใช้จริง
- **ไม่เปลี่ยนตรรกะธุรกิจ** — FIFO ต้นทุน สิทธิ์ RLS คงเดิมทั้งหมด รอบนี้แตะแต่ชั้นแสดงผล
- **ไม่ลงไลบรารี UI ใหม่** — ไม่เอา component library เข้ามาเพื่อสิ่งที่เขียนเองได้
  โปรเจกต์นี้ตั้งใจให้ bundle เล็กมาตั้งแต่ต้น (ตอนนี้ 103 kB shared)
- **ไม่ทำโหมดมืด** — ยังไม่มีใครขอ และเพิ่มงานทดสอบสีเป็นเท่าตัว

## ส่วนที่ 5 — เรื่องที่ยังต้องตัดสินใจ

**5.1 มือถือจะเอายังไง** — คุณเลือก "คอมเป็นหลัก" แต่ถ้าวันหนึ่งต้องเช็คออเดอร์ตอนอยู่นอกร้าน
เมนูข้างจะใช้ไม่ได้ ทางเลือกคือทำให้ยุบเป็นปุ่มแฮมเบอร์เกอร์เมื่อจอแคบ — เพิ่มงานไม่มาก
แต่ต้องตัดสินตอนนี้เพราะกระทบโครง

**5.2 ตัวเลขงานค้างข้างเมนู** ต้องนับจากฐานข้อมูลทุกครั้งที่โหลดหน้า
ถ้าให้ทุกหน้านับ จะยิง query เพิ่มทุกครั้ง ทางเลือกคือนับใน layout ครั้งเดียว
แล้วส่งต่อ หรือทำเป็น view เดียวที่ตอบทุกตัวเลขในรอบเดียว

**5.3 หน้ารายงานกำไร** ตอนนี้ยาวมากและมีห้าส่วนในหน้าเดียว
ยังไม่ได้เสนอให้แยก เพราะไม่แน่ใจว่าคุณดูมันบ่อยแค่ไหนและดูส่วนไหนจริง
